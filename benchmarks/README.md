# Benchmarks

指标仅供同版本横向对比，不构成对标的企业的评价；上市与非上市标的的指标不可直接相比。

## 用途

版本发布前的固定跑批：2–3 个固定标的（上市／非上市／技术型各一）＋干净环境，记录「耗时＋动作数＋产物质量」，作为该版本的公开基线。任何人可在同版本、同环境下重跑同一标的做横向验证。

## 指标口径

| 指标 | 性质 | 说明 |
|---|---|---|
| 动作数（工具调用次数） | 评分指标 | 跨环境对比**以动作数为准**；墙钟仅同环境内有效 |
| 墙钟（四段秒数） | 记录项 | 必带环境标签（Windows 本机 / Linux 沙盒），跨环境不可比 |
| 缺口承载率 | 评分指标 | gap-list 中 open 缺口被 missing 块／括注承载的比例 |
| 返工轮次 | 评分指标 | validate／gap 门禁失败后重交 report.json 的次数 |
| 来源数 | 记录项（只记不评） | 「越多越好」会诱发堆来源；上市与非上市本不可比 |
| 悬空引用数／引用闭环率 | 机械 tripwire | 闭环由 validate() errors 级强制，预期恒 100%；出现闭环失败＝门禁被绕过或数据被破坏，阻塞发布 |

## 失败分级

- 硬指标失败（校验不过／质量回归）＝**阻塞发布**；
- 环境性失败（网络／工具不可用）＝**记录放行、事后补跑**——基准跑批是每次发布的固定机时成本，环境故障不应卡死发布。

## 数据归属

- 基线指标＋**标的名称具名公开**（复现性优先，任何人可跑同一标的横向对比）；run-log 过程细节一律不公开，仅本地留存。
- 风险已知情接受：具名意味着「分析过某标的」这一事实本身公开。
- 应急摘除：若日后发现某标的属敏感关系，从公开基线摘除该条并在本 README 留说明（代价：失去该标的公开锚定）。

## 文件

- `run_baseline.py`——渲染校验段机械跑批：validate → gap 门禁 → render 计时，校验产物闭环，追加一行到 `baseline.json`。研究／写作段由 agent 侧 run-log 记录（spec §8.1），本脚本不覆盖。
- `baseline.json`——各版本公开基线行。
